## cloud Server

### 폴더 구조

기능별로 큰 분류만 나누며, 개별 뷰어마다 별도 폴더를 만들지 않습니다.

```text
app/                   페이지 및 API 진입점
components/
  auth/                인증 및 사용자 UI
  ui/                  공통 UI
  drive/               목록, 선택, 메뉴, 공유·이동 다이얼로그
  previews/            파일 뷰어, 스타일, 파싱 워커
  transfers/           업로드 메뉴 및 진행 상황 UI
lib/
  server/              인증 연동, DB, 권한 및 서버 조회
  drive/               드라이브 API 클라이언트와 목록·선택 로직
  files/               파일 형식, 다운로드 이름·구조, HTTP 범위
  previews/            미리보기 파서 및 탐색 로직
  transfers/           업로드 큐 및 폴더 업로드·다운로드
prisma/                DB 스키마와 SQL
tests/                 자동화 테스트
scripts/               개발·빌드 보조 스크립트
public/                공개 정적 파일
```

여러 기능에서 사용하는 공통 유틸리티와 사용자 세션은 `lib/` 바로 아래에 유지합니다.

### 인증 서버 연결

`.env`의 `AUTH_URL`은 프로토콜을 포함한 주소여야 합니다.
예: 로컬 개발 `http://localhost:3000`, HTTPS 배포 `https://auth.example.com`.
설정 변경 후 개발 서버를 재시작하세요.

`WEB_URL`은 브라우저에서 접속하는 Cloud 주소를 프로토콜과 포트까지 포함해 설정합니다.
예: `http://web.example.com:3001`. `AUTH_URL`은 별도의 로그인 서버 주소입니다.
파일 수정·로그아웃 요청의 Origin은 공개 Host 또는 `WEB_URL`과 정확히 일치해야 합니다.
HTTPS 프록시 뒤에서 내부 주소가 localhost로 보이는 경우 `WEB_URL`에 외부 HTTPS 주소를 설정하세요.
포트 3001과 3002는 서로 다른 Origin이며, 로그인 서버 Origin을 파일 수정용으로 허용하지 않습니다.

브라우저는 같은 출처의 `/api/user`, `/api/logout`을 호출하고,
이 서버가 `AUTH_URL`의 해당 API로 `session_id` 쿠키만 전달합니다.
사용자 응답은 캐시하지 않습니다. 브라우저에서 인증 서버로 직접 요청하지 않으므로
이 조회 경로에는 CORS 설정이 필요 없습니다.

이 방식은 **Cloud 도메인에 session_id 쿠키가 전달되는 경우**에 동작합니다.
인증 서버만의 host-only 쿠키는 Cloud 서버에서 읽을 수 없습니다.
같은 부모 도메인의 서비스라면 인증 서버에서 `Domain=example.com; Path=/; HttpOnly; Secure; SameSite=Lax`
형태로 필요한 하위 도메인에 공유할 수 있습니다. 기존 쿠키는 설정 변경 후 재로그인이 필요합니다.
부모 도메인 전체에 공유되는 세션 쿠키이므로 관련 하위 도메인이 모두 신뢰 가능해야 합니다.
로컬에서는 두 앱 모두 `localhost`로 접속하세요. `127.0.0.1`과 섞어 쓰지 마세요.
서로 다른 부모 도메인인 경우 쿠키를 공유할 수 없고, 인증 콜백에서 Cloud 전용 세션을 만드는 흐름이 필요합니다.

`/api/user`가 `401 NO_SESSION`을 반환하면 Cloud로 쿠키가 오지 않는 상태이고,
`401 INVALID_SESSION`이면 쿠키는 전달됐지만 인증 서버에서 유효하지 않은 상태입니다.
`503 AUTH_URL_INVALID`는 주소 설정 오류, `502 AUTH_UNAVAILABLE`은 연결 오류입니다.
원래 인증 쿠키의 Domain/Path를 그대로 유지한 Set-Cookie 응답을 전달합니다.
로그인·회원가입·계정 설정은 인증 서버에서 처리합니다.

루트 페이지 `/`와 드라이브 페이지 `/drive`는 서버에서 중앙 인증 서버의 세션을 확인합니다.
쿠키 누락·만료 또는 사용자 정보가 없는 경우 `AUTH_URL`의 `/login`으로 이동합니다.
유효한 세션은 루트에서 `/drive`로 이동하며, `/drive`에 직접 접속하면 드라이브 화면을 표시합니다.
인증 서버 연결·설정 오류나 잘못된 응답은 로그인 페이지로 보내지 않고 재시도 안내를 표시합니다.
세션 조회는 캐시하지 않으며 브라우저의 사용자 캐시나 쿠키 존재 여부만으로 로그인 상태를 판단하지 않습니다.

### Cloud API

모든 파일·폴더 요청은 `lib/server/cloud.ts`의 `getCloudOwnerId(request)`에서 세션을 검증합니다.
요청의 `session_id`를 인증 서버 `/api/user`에 전달하고 성공 응답의 `result.id`를 소유자로 사용합니다.
인증 서버의 `null` 또는 `{ "result": null }` 응답과 쿠키 누락·만료는 `401`로 처리합니다.
인증 서버 연결·응답 오류는 `502` 또는 설정 오류 `503`이며 임시 ID로 대체하지 않습니다.
클라이언트가 보내는 사용자 ID와 프로필 정보는 소유자 결정에 사용하지 않습니다.
공유 권한이 없는 다른 사용자의 항목 접근은 `404`로 거절합니다.
공유받은 항목은 보기·편집 권한에 따라 접근하며 공유 관리·이동·삭제는 소유자만 가능합니다.
기존 `temporary-cloud-user` 데이터는 자동으로 실제 계정에 이전되지 않습니다.
공유 기능에는 아래의 추가 공유 테이블 SQL이 필요합니다. 이미 적용한 SQL은 재실행하지 않습니다.
드라이브 UI는 실제 API로 목록 조회·업로드·폴더 생성·이름 변경·즐겨찾기·삭제·복원·다운로드를 처리합니다.
파일·폴더 ID는 서버에서만 생성하고 새로고침 후에도 파일이 유지됩니다.

파일 정보는 PostgreSQL `cloud_item` 테이블에, 원본은 프로젝트의 `.cloud-storage/`에 저장됩니다.
원본 저장 폴더는 `public` 외부에 있으며 API를 통해서만 다운로드합니다.
서버 재시작 후에도 데이터가 유지됩니다. 배포할 때는 DB와 이 폴더를 함께 백업하고,
지속 가능한 디스크를 연결하세요. 현재는 단일 서버용 저장 방식입니다.

새 환경 설정:

```sh
# .env에 DATABASE_URL 설정 후, 기존 auth 테이블을 변경하지 않는 추가 SQL 실행 (최초 1회)
npx prisma db execute --file prisma/cloud-schema.sql
npx prisma db execute --file prisma/cloud-sharing.sql
npx prisma db execute --file prisma/cloud-storage-quota.sql
npx prisma db execute --file prisma/cloud-public-links.sql
npx prisma generate
npm run dev
```

이미 cloud 테이블을 만든 환경에서는 SQL을 다시 실행하지 않습니다.
DB 없이 API를 호출하면 `503 STORAGE_UNAVAILABLE`을 반환합니다.

### 저장용량 제한

`cloud_storage`에는 중앙 인증 서버 UUID인 `userId`, `usedBytes`, `limitBytes`, `updatedAt`만 저장합니다.
기본 최대 용량은 기존 게이지와 동일한 10 × 1024³ 바이트입니다. 이름·핸들·프로필은 복제하지 않습니다.
`/api/drive/storage`는 `{ bytes, limitBytes }`를 반환하며 화면은 이 제한값을 사용합니다.

파일의 `ownerId`는 기존 폴더 접근 권한을 유지하고, `storageOwnerId`는 최초 업로더 UUID를 기록합니다.
다른 사람의 공유 폴더에 업로드해도 업로더의 용량을 사용합니다. 공유·이동·이름 변경·즐겨찾기는
사용량을 바꾸지 않고, 휴지통도 포함하며 완전 삭제할 때만 해당 업로더에게 용량을 돌려줍니다.
폴더 자체는 용량을 사용하지 않습니다. 업로드 등록·용량 증가는 같은 트랜잭션에서 처리하며,
동시 업로드도 DB의 조건부 증가로 제한합니다. 용량 부족은 `413 STORAGE_QUOTA_EXCEEDED`입니다.

기존 환경에도 `prisma/cloud-storage-quota.sql` 실행과 `npx prisma generate`가 필요합니다.
마이그레이션은 기존 파일을 삭제하지 않으며, 휴지통을 포함해 초기 사용량을 집계합니다.
과거 업로더 기록이 없으므로 기존 파일은 현재 `ownerId`를 용량 부담자로 초기화합니다.
이미 10GB를 초과한 계정의 파일은 유지하며, 사용량을 줄이기 전에는 새 업로드만 제한됩니다.
운영 중 적용할 때는 업로드·삭제를 잠시 중단하고 마이그레이션 후 앱을 재시작하세요.

### 파일 링크 공유

파일의 공유 창에서 링크를 활성화하고 접근 범위를 선택합니다. 폴더 링크는 현재 지원하지 않습니다.

- `내가 공유한 사용자만` (`RESTRICTED`): 소유자 또는 직접·상위 폴더 공유 권한이 있는 로그인 사용자만 열람합니다. 로그인만 한 다른 사용자는 접근할 수 없습니다.
- `링크가 있는 누구나` (`PUBLIC`): 링크를 가진 사람은 로그인 없이 해당 파일을 미리보기·다운로드할 수 있습니다. 링크를 전달받은 다른 사람도 접근할 수 있으므로 민감한 파일에는 사용하지 마세요.
- `링크 공유 끄기`: 링크 기록을 삭제합니다. 다시 활성화하면 새로운 링크가 발급되며, 기존 링크는 사용할 수 없습니다.

`cloud_link`는 파일당 하나의 256비트 무작위 토큰과 접근 범위를 저장합니다. 파일 UUID는 링크 인증 수단이 아닙니다.
소유자만 `/api/links`에서 링크를 조회·활성화·변경·삭제할 수 있고, 편집 공유 권한으로는 관리할 수 없습니다.
`/s/{token}`은 열람 전용 페이지이며 기존 뷰어를 사용합니다. 미지원 형식은 다운로드 안내를 표시합니다.
`/api/public/files/{token}`과 `/content`는 매 요청마다 링크 상태와 권한을 확인하고,
사용자 UUID·저장 키·부모 경로·다른 파일 목록을 반환하지 않습니다. 내용 응답은 Range/HEAD를 지원합니다.

파일 또는 상위 폴더를 휴지통으로 이동하면 링크가 해제되고, 복원해도 옛 링크는 살아나지 않습니다.
범위 변경·공유 권한 해제는 다음 요청부터 적용됩니다. 이미 다운로드한 파일이나 전달된 바이트는 회수할 수 없습니다.
공유 페이지는 검색 색인을 차단하고 referrer를 보내지 않으며, 응답은 캐시하지 않습니다.
앱 요청 로그에서는 토큰을 가립니다. 외부 프록시·분석 도구 로그에서도 링크 토큰을 가리도록 설정하세요.
기존 환경은 `prisma/cloud-public-links.sql` 실행, `npx prisma generate`, 앱 재시작이 필요합니다.

| Method | URL | 기능 |
| --- | --- | --- |
| GET | `/api/files` | 현재 폴더의 내 파일 목록 |
| POST | `/api/files` | 파일 하나 업로드 |
| GET | `/api/files/:id` | 파일 정보 |
| PATCH | `/api/files/:id` | 이름 변경, 폴더 이동, 즐겨찾기, 복원 |
| DELETE | `/api/files/:id` | 파일을 휴지통으로 이동 |
| DELETE | `/api/files/:id?permanent=true` | 휴지통 파일과 원본 완전 삭제 |
| GET | `/api/files/:id/content` | 원본 다운로드 |
| GET | `/api/folders` | 현재 폴더의 내 폴더 목록 |
| POST | `/api/folders` | 폴더 생성 |
| GET | `/api/folders/:id` | 폴더 정보 |
| PATCH | `/api/folders/:id` | 이름 변경, 이동, 즐겨찾기, 복원 |
| DELETE | `/api/folders/:id` | 폴더와 활성 하위 항목을 휴지통으로 이동 |
| DELETE | `/api/folders/:id?permanent=true` | 휴지통 폴더와 하위 항목 완전 삭제 |

목록 쿼리: `parentId` (없으면 루트), `q` (이름 검색), `starred=true`,
`trash=true` (전체 휴지통), `limit` (기본 50, 최대 100), `offset` (기본 0).
기존 파일·폴더 API의 `scope=all`은 로그인한 사용자의 전체 폴더에 있는 항목을 조회합니다.
드라이브 UI는 이 전체 목록을 초기 로드하지 않고 아래의 화면별 조회 API를 사용합니다.

### 화면별 목록 조회

- `GET /api/drive`: 현재 위치·공유·즐겨찾기·최근·휴지통의 파일과 폴더를 합쳐 한 페이지(기본 50개, 최대 100개)만 반환합니다.
- `area`, `parentId`, `scope=current|all`, `q`, `kind`, `sort=modified|name|size`, `starredOnly`, `from`, `to`, `limit`, `offset`을 받습니다.
- 검색·카테고리·날짜·개인 즐겨찾기·정렬은 DB에서 페이지를 자르기 전에 적용합니다. 정렬은 폴더 우선이며 ID를 마지막 기준으로 사용해 동일 조건에서 안정적인 순서를 유지합니다.
- 응답은 `{ items, context, path, total, limit, offset }`입니다. `context`는 반환된 항목의 접근 가능한 부모 폴더 정보이며 전체 폴더 트리가 아닙니다. 상위 폴더에 접근 권한이 없으면 해당 경로는 노출하지 않습니다.
- 홈 기본 조회는 최근 파일 8개·즐겨찾기 6개·직접 공유받은 항목 5개의 합집합만 보냅니다. 홈 검색은 전체 접근 가능한 위치에서 검색한 결과를 페이지로 보냅니다.
- UI는 ‘더 보기’를 누를 때만 다음 50개를 요청합니다. 위치·검색·정렬 변경 시 새 목록으로 바꾸고 이전 요청을 취소/무시합니다. 검색 입력에는 250ms 지연을 적용합니다.
- `GET /api/drive/storage`는 휴지통을 포함한 내 업로드 사용량과 최대 용량을 반환합니다. 공유 폴더의 내 업로드도 포함하며, 최초 접속·업로드 완료·완전 삭제 시 갱신합니다. 탭 이동마다 전체 파일 목록으로 계산하지 않습니다.
- `GET /api/drive/neighbors?itemId=...&sort=...`는 실제 같은 폴더의 접근 가능한 미리보기 이전·다음 파일만 반환합니다. 페이지 밖의 파일과 미지원 형식 건너뛰기도 서버에서 처리합니다.
- 이동 창도 열었을 때 탐색 중인 폴더의 하위 폴더만 페이지별로 조회합니다. 서버의 소유권·순환 이동 검증은 그대로 유지됩니다.

화면별 통합 검사: `node --test tests/drive-pagination.test.mjs` (로컬 Cloud DB에 테스트 임시 데이터 생성·정리).

### 기존 파일 API 상세
`/api/files/:id/content?preview=true`는 PNG/JPEG/GIF/WebP/AVIF와 영상·음원 MIME을 inline으로 반환하며 그 외 파일은 다운로드 처리합니다.
원본 API는 인증·접근 권한 검증 후 단일 바이트 Range 요청에 206, 범위가 유효하지 않으면 416을 반환하여 미디어 탐색을 지원합니다.
응답은 `{ items, total, limit, offset }`입니다. 항목의 `size`는 바이트 단위입니다.
생성·수정·단건 조회는 `{ item }`, 삭제 성공은 본문 없는 `204`를 반환합니다.
항목 ID와 저장소 파일명은 서버에서 생성합니다.

드라이브 UI의 **새로 만들기** 메뉴에서 새 폴더 생성과 파일 업로드를 선택할 수 있습니다.
폴더와 파일은 하나의 목록 또는 격자에 표시하며, 폴더를 먼저 정렬합니다.
본문은 상단 제목(폴더 경로), 카테고리·정렬·보기 선택, 파일 목록 순서로 구성하며 홍보 배너와 중복 제목·하단 안내는 표시하지 않습니다.
드라이브 화면은 창 높이에 고정하며 헤더·왼쪽 메뉴·제목·도구 모음은 유지하고 오른쪽 파일 목록만 스크롤합니다. 낮은 화면의 왼쪽 메뉴는 별도로 스크롤할 수 있습니다.
목록 보기의 이름·소유자·수정한 날짜·파일 크기 헤더도 파일 영역 상단에 고정하며 라이트·다크 테마에서 불투명 배경을 유지합니다.
헤더 검색창은 `components/auth/searchBar.tsx`의 둥근 UI를 사용하며 입력 즉시 파일명으로 검색합니다.
상세 검색에서 현재 위치/전체 폴더, 파일 종류, 개인 즐겨찾기, 수정 날짜 범위를 조합할 수 있습니다.
날짜는 한국 시간 기준이며 종료일도 포함합니다. 파일 종류는 목록의 카테고리 메뉴와 같은 상태를 사용합니다.
내 드라이브의 전체 폴더 검색에는 접근 가능한 공유 항목도 포함하며 공유된 파일에서는 공유 하위 항목까지 검색합니다.
휴지통은 휴지통 항목만, 즐겨찾기는 내 별표 항목만 검색합니다. 검색 초기화 또는 폴더·메뉴 이동 시 조건을 초기화합니다.

목록 행이나 격자 카드를 더블클릭하면 폴더는 해당 폴더로 이동하고 이미지·텍스트는 전체 화면 미리보기, 나머지 파일은 기존 정보 창을 엽니다.

스프레드시트는 XLSX·XLS·XLSM·XLSB·XLT·XLTX·XLTM·ODS·OTS·CSV·TSV를 읽기 전용 전체 화면으로 엽니다.
시트 탭, 고정 행/열 라벨, 병합 셀, 100행 단위 페이지 이동, 셀 전체 값·수식 확인을 제공합니다.
보기 메뉴에서 줄바꿈·수식 표시·글자 크기를 바꿀 수 있으며 기존 파일 메뉴·다운로드를 유지합니다.
수식은 실행하거나 재계산하지 않고 파일에 저장된 결과만 표시합니다. CSV/TSV의 선행 0과 수식처럼 보이는 문자열도 그대로 표시합니다.
차트·이미지·원본 서식 재현·매크로 실행·암호 파일·Numbers 파일은 지원하지 않습니다.
최대 20 MB, 처음 50개 시트 중 숨기지 않은 시트, 시트당 첫 5,000행 범위와 사용 영역의 100열까지만 표시합니다.
파싱은 별도 Worker에서 처리하고 20초를 초과하면 중단합니다. 모든 파일 요청은 기존 서버의 로그인·공유 권한 검증을 사용합니다.
같은 줄 오른쪽의 정렬 메뉴에서 최근 수정순(최신 먼저), 이름순, 파일 크기순(큰 파일 먼저)을 선택합니다.
정렬 시 폴더가 먼저 표시되며 목록·격자 보기 모두 같은 순서를 사용합니다.
현재 열린 폴더에 저장되며, 제목에 표시된 각 폴더 경로를 눌러 탐색합니다.
파일·폴더의 옵션 창에서 **이동**을 누르고 대상 폴더를 탐색한 뒤 **여기로 이동**을 선택하세요.
목록·격자의 **…** 드롭다운에서 정보 보기, 이름 바꾸기, 파일 다운로드를 선택합니다.
파일·폴더의 목록 행 또는 격자 카드 전체 영역을 우클릭해도 같은 메뉴가 커서 위치에 열립니다.
이름·소유자 등의 목록 헤더와 그 아래 빈 공간, 격자 카드 사이·아래 빈 공간에서는
기존 **새로 만들기**와 같은 메뉴가 열립니다. 같은 아이콘·순서·너비·여백으로
**새 폴더**와 **파일 업로드**를 제공하며 현재 폴더에 추가합니다. 빈 목록에서도 사용할 수 있습니다.
빈 목록의 업로드·폴더 생성 안내는 내 드라이브에만 표시하며, 나머지 메뉴에서는 “파일이 없습니다.” 문구만 표시합니다.
상단 검색·안내·도구 모음에는 적용하지 않으며 파일·폴더와 버튼은 기존 동작을 유지합니다.
휴지통, 공유 목록 루트, 보기 전용 공유 폴더처럼 업로드할 수 없는 위치에서는 메뉴를 열지 않습니다.
화면 가장자리에서는 메뉴가 화면 안에 표시되도록 위치가 조정되며, 바깥 클릭이나 Esc로 닫습니다.
정보 보기와 이름 바꾸기는 별도 창으로 열립니다. 일반 폴더에는 다운로드 메뉴가 표시되지 않습니다.
휴지통 항목에는 정보 보기·복원·완전 삭제만 표시합니다. 완전 삭제는 확인 후 실행하며 복원할 수 없습니다.
내 드라이브 루트로도 이동할 수 있습니다. 폴더 자체나 그 하위 폴더는 이동 대상으로 제외하며,
서버에서도 소유권, 순환 구조, 같은 이름 충돌을 검증합니다.
목록·격자에서 파일이나 폴더를 다른 폴더로 끌어놓아 이동할 수도 있습니다.
상단 경로의 상위 폴더·내 드라이브, 사이드바 내 드라이브도 이동 대상입니다.
유효한 대상은 파란색으로 강조되며 현재 위치·자기 자신·하위 폴더로의 드롭은 무시합니다.
컴퓨터에서 끌어온 파일은 기존처럼 현재 열린 폴더에 업로드됩니다.

### 사용자 공유

공유받은 파일·폴더도 보기/편집 권한 모두 개인 즐겨찾기로 지정할 수 있습니다.
목록의 별표 또는 목록·격자의 옵션/우클릭 메뉴에서 변경하며 내 항목과 함께 즐겨찾기에 표시합니다.
공유 대상별 `cloud_share.starred`에 저장하므로 소유자나 다른 수신자의 별표에는 영향이 없습니다.
상속받은 항목의 개인 설정은 `role = NULL` 행으로 저장하며 접근 권한이나 직접 공유로 취급하지 않습니다.
공유 해제·항목 이동·휴지통 이동으로 접근 권한을 잃으면 즐겨찾기 목록에서도 제외됩니다.
공유 해제 시 직접 공유 행은 별표 여부와 관계없이 삭제하며, 접근 권한을 잃은 하위 항목의 개인 설정도
같은 트랜잭션에서 삭제합니다. 다른 공유 경로로 여전히 접근 가능한 하위 항목의 별표는 유지합니다.
이전 정책으로 남은 접근 불가능한 개인 설정은 `npx prisma db execute --file prisma/cloud-share-cleanup.sql`로
한 번 정리할 수 있습니다. 현재 로컬 DB에는 적용했습니다.
기존 DB에는 아래 추가 SQL 적용과 클라이언트 생성 후 개발 서버 재시작이 필요합니다.
현재 로컬 DB에는 이미 적용했습니다.

```sh
npx prisma db execute --file prisma/cloud-shared-stars.sql
npx prisma generate
```

공유받은 항목의 소유자는 실제 표시 이름과 `@핸들`로 목록·격자·정보 창에 표시합니다.
소유자 아이콘을 좌클릭하면 작은 프로필 메뉴에 이름, 핸들, 소개 문구, 프로필 이미지를 표시합니다.
메뉴를 열 때마다 Cloud의 `GET /api/items/:id/owner`가 세션·항목 접근 권한을 확인하고,
UUID로 현재 핸들을 확인한 뒤 중앙 `POST /api/user/handle`로 공개 프로필을 가져옵니다.
핸들 조회의 사용자 UUID가 파일 소유자와 같은지 다시 확인하며 브라우저에는 공개 프로필 필드만 전달합니다.
프로필·이미지가 없거나 조회 실패 시 대체 표시와 재시도 버튼을 제공하며 바깥 클릭·Esc로 닫습니다.
Cloud는 접근 권한 확인 후 인증 서버의 `POST /api/user/uuid`에 `{ "uuid": "사용자 UUID" }`를 보내
현재 이름·핸들을 조회합니다. 응답은 `{ "result": { "handle": "...", "displayName": "..." } }`이며
UUID 응답에 `id`는 필요하지 않습니다. `session_id` 쿠키만 전달하고 중앙 응답의 추가 필드는 전달하지 않습니다.
공유한 사람과 공유 대상의 이름·핸들 변경은 다음 목록 조회에 반영되며 Cloud DB에는 프로필을 저장하지 않습니다.
같은 요청 안에서는 UUID별 조회를 합치고 최대 5건을 동시에 조회합니다. 요청 간 프로필 캐시는 없습니다.
프로필 조회 실패 시 파일 접근 권한은 유지하고 사용자 정보를 불러올 수 없다고 표시합니다.
기존 DB에는 다음 SQL을 한 번 적용한 뒤 클라이언트를 생성하고 개발 서버를 재시작하세요.
이 SQL은 중복 프로필 테이블과 공유 테이블의 이메일·핸들·이름 열만 제거합니다.
파일·폴더, 사용자 UUID, 공유 권한은 유지됩니다. 현재 로컬 DB에는 이미 적용했습니다.

```sh
npx prisma db execute --file prisma/cloud-central-profiles.sql
npx prisma generate
```

파일·폴더의 **… → 공유**에서 핸들을 입력하고 보기/편집 권한을 선택해 사용자를 추가합니다.
세 명 이상도 제한 없이 한 사람씩 추가하며 각자의 권한 변경과 공유 해제가 가능합니다.
같은 사용자를 중복 추가하면 `409 ALREADY_SHARED`입니다. 수신자는 **공유된 파일**에서 확인합니다.
알림 메일이나 메시지를 전송하지 않으며 등록된 계정에 접근 권한을 직접 부여합니다.

Cloud는 `AUTH_URL`의 `POST /api/user/handle`로 `{ "handle": "cloud" }`를 보내며
`session_id`만 전달합니다. 응답은 `{ "result": { "id": "...", "handle": "cloud", "displayName": "..." } }`
형식을 사용합니다. 반환된 사용자 ID로 공유하며 클라이언트의 임의 사용자 ID는 공유 생성에 사용하지 않습니다.
`role`, `bio`, `avatarUrl` 등 조회 응답의 추가 필드는 저장하지 않습니다.
Cloud DB에 인증 사용자의 테이블이나 비밀번호를 복제하지 않습니다.

| 권한 | 허용 작업 |
| --- | --- |
| 보기 | 공유된 파일·폴더 조회, 파일 다운로드·이미지 미리보기 |
| 편집 | 보기 기능 + 이름 변경, 공유 폴더 안에 업로드·폴더 생성 |
| 소유자 | 전체 관리, 공유 대상·권한 관리, 이동, 삭제·복원·완전 삭제 |

편집자가 공유 폴더에 추가한 항목은 폴더 소유자의 저장소와 용량에 속합니다.
폴더 공유는 현재·미래 하위 항목에 상속됩니다. 상속된 권한은 공유 창에 별도로 표시하며
상위 폴더에서 변경합니다. 직접 공유를 해제해도 상위 폴더의 권한이 있으면 접근할 수 있습니다.
여러 공유 경로가 있으면 더 높은 권한이 적용됩니다. 폴더 밖으로 옮기면 해당 폴더의 상속 권한은 사라집니다.
휴지통 항목은 수신자에게 보이지 않으며 복원 시 남아 있는 공유가 다시 적용됩니다.
완전 삭제 시 해당 항목의 공유 기록도 함께 삭제됩니다. 권한은 매 요청마다 다시 검증합니다.

기존 DB에는 최초 한 번 다음 추가 SQL과 클라이언트 생성을 실행하세요.
이번 작업의 현재 로컬 Cloud DB에는 이미 적용했습니다.

```sh
npx prisma db execute --file prisma/cloud-sharing.sql
npx prisma generate
```

| Method | URL | 기능 |
| --- | --- | --- |
| GET | `/api/shared?limit=100&offset=0` | 공유받은 항목과 접근 가능한 하위 항목 |
| GET | `/api/shares?itemId=...` | 소유자의 직접·상속 공유 목록 |
| POST | `/api/shares` | `{ itemId, handle, role: "VIEWER" 또는 "EDITOR" }`로 추가 |
| PATCH | `/api/shares` | `{ itemId, userId, role }`로 권한 변경 |
| DELETE | `/api/shares` | `{ itemId, userId }`로 직접 공유 해제 |

폴더 생성 JSON:

```json
{ "name": "3D 프로젝트", "parentId": null }
```

파일 업로드는 `multipart/form-data`로 `file` 필드 하나를 전송합니다.
선택적으로 `parentId`, `name`을 함께 지정할 수 있습니다. 파일 최대 크기는 100 MB입니다.
요청 전체에도 크기 제한을 적용하지만 multipart 파서는 파일을 메모리에 읽습니다.
여러 파일은 각각의 요청으로 업로드하세요.

```js
const form = new FormData();
form.append("file", fileInput.files[0]);
// form.append("parentId", folderId);
const response = await fetch("/api/files", { method: "POST", body: form });
const { item } = await response.json();
```

수정은 필요한 필드만 전달합니다:

```json
{ "name": "최종 모델.glb", "parentId": null, "starred": true }
```

복원은 `{ "restore": true }`를 전달합니다. 같은 위치의 동일 이름은 `409 NAME_EXISTS`입니다.
복원 시 이름 충돌은 확장자를 유지한 ` (복원 1)` 접미사로 구분합니다. 부모 폴더가 휴지통에 있으면
기본적으로 내 드라이브 루트로 복원하며, `name`과 `parentId`를 명시할 수도 있습니다.
폴더 삭제는 하위 활성 항목까지 같은 `trashBatchId`로 표시합니다. 폴더 복원은 이 묶음만 복원하므로
그 전에 따로 삭제된 하위 항목은 휴지통에 남습니다. 하위 항목을 따로 복원하면 부모 복원 시 중복 복원하지 않습니다.
소유자만 실행할 수 있으며 폴더 작업은 하위 항목 포함 10,000개까지입니다.
휴지통 이동 시 원본 파일은 복원을 위해 남습니다. `DELETE ...?permanent=true`는 휴지통 항목만
완전 삭제하며 파일 원본과 DB 정보를 제거합니다. 휴지통에 없는 항목은 `409 NOT_IN_TRASH`입니다.
폴더 완전 삭제는 예전에 따로 삭제했던 하위 항목까지 포함하고 자식부터 DB 기록과 공유 기록을 제거합니다.
원본은 먼저 `.deleting` 이름으로 임시 이동한 뒤 DB 커밋 후 제거합니다. DB 실패 시 임시 원본을 되돌려
재시도할 수 있으며, 원본이 이미 없는 휴지통 파일도 DB 정보를 정리할 수 있습니다.
프로세스 강제 종료나 커밋 후 디스크 정리 실패 시 `.cloud-storage`의 `.deleting` 파일이 남을 수 있습니다.
`Cloud purge cleanup required`/`Cloud purge rollback failed` 로그는 운영자가 DB 상태와 대조해 복구·정리해야 합니다.

기존 Cloud DB에는 추가 SQL을 적용하고 Prisma 클라이언트를 다시 생성하세요(현재 로컬 DB에는 적용됨).

```sh
npx prisma db execute --file prisma/cloud-folder-trash.sql
npx prisma generate
```

오류 응답은 `{ error: { code, message } }`이며 잘못된 요청 `400`, 없는 항목 `404`,
이름 충돌·폴더 상태 충돌 `409`, 크기 초과 `413`, 업로드 형식 오류 `415`를 사용합니다.

파일/폴더는 한 번 클릭으로 선택하고 더블클릭으로 엽니다. Ctrl(또는 macOS Command) 클릭은 개별 선택을
추가/해제하고, Shift 클릭은 현재 표시 순서대로 범위를 선택합니다. Ctrl+Shift는 기존 선택에 범위를 추가합니다.
빈 공간 클릭 또는 Esc로 선택을 해제합니다. 위치·검색·정렬·보기 변경 시 선택은 초기화됩니다.
선택된 항목을 폴더/경로/내 드라이브 메뉴로 드래그하면 함께 이동합니다. 선택되지 않은 항목을 드래그하면 그 항목만 이동합니다.
폴더와 하위 항목을 함께 선택한 경우 폴더만 이동하여 내부 구조를 유지합니다. 공유받은 항목과 휴지통 항목은
이동할 수 없고, 선택 그룹 중 하나라도 목적지로 이동할 수 없으면 드롭을 차단합니다.
실제 이동은 기존 API를 항목별로 순차 호출하며 일부 실패 시 성공 항목은 유지하고 실패 내용을 알립니다.
선택 시 카테고리 영역은 `X(선택 해제) → 선택 개수 → 다운로드·공유·즐겨찾기·이동·휴지통` 작업 바로 바뀝니다.
이동 버튼은 여러 항목에 공통으로 사용할 목적지 선택 창을 열며, 이미 목적지에 있는 항목은 건너뜁니다.
휴지통 버튼은 대상 확인 후 항목별로 처리합니다. 일부 실패 시 성공 항목만 선택에서 제거하고 실패 항목은 유지합니다.
공유받은 항목은 이동/휴지통 처리할 수 없습니다. 폴더와 그 하위 항목을 함께 선택하면 폴더 단위로 한 번만 처리합니다.
선택을 해제하면 카테고리 UI로 돌아오며, 기존 별도 선택 안내 행은 표시하지 않습니다.
여러 파일 다운로드는 원본 형식을 유지한 ZIP 하나로 제공하고, 동일 파일명은 접미사로 구분합니다.
`POST /api/files/download`는 `{ itemIds: [...] }`를 받고 최대 100개의 파일·폴더 선택을 서버에서 권한 확인한 뒤

휴지통/접근 불가 항목이 섞이면 전체 다운로드를 거절하며, 선택 폴더 안의 휴지통 항목은 제외합니다.
폴더와 그 하위 파일을 함께 선택하면 하위 파일은 중복 포함하지 않습니다.
폴더 다운로드는 `showDirectoryPicker`를 지원하는 보안 연결(HTTPS/localhost)에서 저장 위치를 선택해
압축 없이 로컬 폴더로 저장합니다. 지원하지 않는 브라우저에서는 ZIP으로 대체합니다.
이때 `{ itemIds: [...], mode: "manifest" }`로 권한 검증된 트리만 받고 각 파일은 기존 인증 다운로드 API로
직접 로컬 쓰기 스트림에 연결합니다. 기존 이름이 있으면 접미사를 붙여 다른 이름으로 저장합니다.
직접 폴더 저장에는 ZIP의 1 GB 제한이 없으며, ZIP/직접 저장 모두 폴더 포함 최대 5,000개 항목과 깊이 제한을 적용합니다.
다운로드 이름은 Windows 금지 문자·예약 장치명·끝의 점/공백을 처리하고 Unicode NFC로 정규화합니다.
단일 다운로드·ZIP 내부 경로·직접 폴더 저장에 동일한 규칙을 적용하며 클라우드의 원래 이름은 변경하지 않습니다.
이름은 UTF-8 기준 최대 240바이트로 줄이되 가능한 한 확장자를 유지합니다. 변환·길이 축소·대소문자 차이로
이름이 겹치면 `(2)`, `(3)` 접미사로 구분하며, 기존 로컬 항목과 충돌할 때도 길이 제한을 유지합니다.
다중 공유는 같은 핸들과 권한을 선택 항목에 적용하며, 이미 직접 공유된 항목의 권한은 바꾸지 않습니다.

즐겨찾기는 모두 별표가 있으면 일괄 해제하고, 그렇지 않으면 일괄 추가합니다.
